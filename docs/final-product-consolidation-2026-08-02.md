# Final Product Consolidation — 2026-08-02

Koschei Web3 Security is entering a revenue-first finalization phase.

## Active product priorities

- canonical token and wallet investigation
- creator launch portfolio and lifecycle evidence
- holder, cluster, launch and actor evidence
- Jupiter read-only exit-liquidity simulation
- Solana program authority and deployment-age evidence
- deterministic signed verdicts and immutable dossier snapshots
- public/customer/owner surfaces that expose the same canonical report

## Deferred cost center

Defense OS remains in the repository but is dormant by default.

- `KOSCHEI_DEFENSE_OS_ENABLED=true` is required to register Defense OS owner routes.
- `KOSCHEI_DEFENSE_AGENT_RUNTIME_ENABLED=true` is still required to run the shadow runtime.
- No Defense worker or sentinel service is currently deployed as a separate Railway service.
- The default production path does not require lab, reproduction, harness, materialization or LiteSVM execution.

This is a prioritization decision, not a deletion. Defense OS can be re-enabled when revenue supports its operational cost.

## Integration contract

The canonical capability report now treats these visible product outputs as explicitly wired contextual capabilities:

- `exit_liquidity`
- `program_security`
- `helius_actor_discovery`

Exit quotes and program authority remain contextual evidence. They do not independently create a verdict or numeric score.
