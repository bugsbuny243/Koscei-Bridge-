Usage and async results

The usage API reports request status, reserved/charged credits, errors, latency, result availability, and completion metadata.

GET /api/v1/usage GET /api/v1/usage?request_id=REQUEST_ID X-API-Key: ARVIS_API_KEY
Credits here are API usage reservation/charge metadata. Do not treat them as a separate verdict, token balance, or evidence score.
SIGNED VERDICT TRUST RULE

Do not integrate against a fabricated sample score.

A consumer should treat a verdict as final only when the response contract marks it signed by the deterministic verdict engine. Inspect the evidence and limitations instead of trusting one display number.

  • signature metadata — verify that the deterministic verdict contract marks the result signed.
  • evidence arms — understand what completed, what remained unavailable, and what was only observed or bounded.
  • ruleset version + triggered rules — preserve the deterministic decision context.
  • decision path + source freshness — know how the result was reached and how current the evidence is.
  • limitations — never convert missing or unresolved evidence into a low-risk assumption.
No model authority: narrative or model output cannot create evidence or alter the authoritative deterministic verdict.
