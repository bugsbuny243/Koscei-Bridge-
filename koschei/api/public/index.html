Koschei Web3 is being built for the security gap between reviewed code and the exact transaction that reaches a signer and the chain. It binds source, build, runtime policy, payload, pinned chain state, invariant evidence, and signing authorization into one fail-closed security path.

Core product

Execution Proof

Koschei verifies that the transaction presented for signing is the transaction produced by the approved source/build/runtime path and tested against pinned chain state. A dashboard score is not an authorization primitive; reproducible evidence is.

Core implemented

Deterministic proof envelope

Source identity, artifact hash, policy hash, calldata identity, invariant set and signer authorization are bound into canonical evidence.

Core implemented

Safe signing gate

Safe transaction identity is recomputed locally. A caller-supplied ALLOW value or presented transaction hash is never authoritative.

Verified fork in validation

Pinned EVM execution

An isolated Anvil fork executes the exact payload against a pinned block before signing and binds the execution receipt to the proof.

Transaction defense

Runtime defense

Node Shield

Node Shield is the runtime containment and attestation layer intended to prove that the artifact and effective runtime authority match the approved deployment policy. It remains behind its live Linux/BPF proof gate and is not presented here as production-complete.

Cross-chain trust

One proof model, chain-specific evidence.

Koschei is not a Solana-only scanner. The control plane is designed around execution and authority evidence that can be adapted to Ethereum/EVM, Solana and other chains. Bridge reserve/supply semantics are already represented in the invariant model; Pi ↔ Solana remains a separate chain-adapter implementation, not a fake EVM wrapper.
